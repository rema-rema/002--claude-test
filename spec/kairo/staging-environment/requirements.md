# ステージング環境構築システム - 要件定義書

## 1. 機能概要

### 1.1 目的
VPN接続・非VPN接続の両方でhttp://home.pocoアクセス時にWebアプリケーションのステージング環境を提供し、自動ログイン機能付きダッシュボードを表示するシステムの構築

### 1.2 ビジネス価値
- **開発効率向上**: ローカル開発とステージング環境の統一体験
- **検証の簡素化**: VPN設定に関係なく同一URLでアクセス可能
- **セキュリティ維持**: 自動ログインによる利便性とセッション管理の両立

## 2. 機能要件

### 2.1 環境構築要件

#### FR-001: /releaseディレクトリ構築
- **概要**: rootディレクトリ直下に/releaseフォルダを作成し、ステージング環境専用のアプリディレクトリを配置
- **詳細**: 
  - `/release/002--claude-test/` の階層でプロジェクトファイルを管理
  - 開発環境（/home/rema/project/002--claude-test/）とは独立した運用
  - ステージング専用の設定ファイル・環境変数を使用

#### FR-002: 統一アクセスポイント実装
- **概要**: VPN接続・非VPN接続に関わらずhttp://home.pocoでWebアプリにアクセス可能
- **詳細**: 
  - 既存のVPN/DNSアクセスシステム（dnsmasq + nginx）を活用
  - nginxプロキシ設定でステージング環境のポート（3001）に転送
  - DNS解決は既存システムをそのまま利用

### 2.2 アプリケーション要件

#### FR-003: Next.js + FastAPIスタック統合
- **概要**: フロントエンド（Next.js）とバックエンド（FastAPI）を統合したWebアプリケーション
- **詳細**: 
  - フロントエンド: Next.js本番ビルド（port 3001）
  - バックエンド: FastAPI（port 8000）
  - プロキシ設定で/api/*へのアクセスをFastAPIに転送

#### FR-004: 自動ログイン・セッション管理機能
- **概要**: ダッシュボードURL直接アクセス時の自動ログイン機能
- **詳細**: 
  - セッション有効: 即座にダッシュボード表示
  - セッション無効: ログイン画面表示
  - Google OAuth統合（既存のモック認証を拡張）
  - HTTPOnly Cookie + JWT によるセキュアなセッション管理

### 2.3 運用要件

#### FR-005: プロセス管理システム
- **概要**: サービスの自動起動・監視・再起動機能
- **詳細**: 
  - systemdサービス化またはPM2による管理
  - サーバー再起動時の自動起動
  - プロセス異常時の自動復旧
  - ヘルスチェック機能（/health エンドポイント）

#### FR-006: ログ・監視機能
- **概要**: アクセスログ・エラーログの適切な管理と監視
- **詳細**: 
  - nginx、Next.js、FastAPIのログを統合管理
  - エラー発生時の通知機能（Discord通知との統合可能性）
  - ログローテーション設定（日次、サイズ制限）
  - 監査ログ機能（認証・認可イベントの記録）

#### FR-007: エラーハンドリング・フォールバック
- **概要**: ネットワーク・認証エラー時の適切な対応
- **詳細**: 
  - FastAPIサーバーダウン時のフロントエンド表示
  - 認証サーバー障害時の一時的アクセス制御
  - オフライン時の適切なエラーメッセージ表示
  - 自動リトライ機能（APIリクエスト失敗時）

## 3. 技術要件

### 3.1 システム構成
```
Internet/VPN → dnsmasq(DNS) → nginx(Proxy) → Next.js(3001) + FastAPI(8000)
```

#### 既存システムとの統合ポイント
- **DNS解決**: 既存dnsmasqを継続利用（/etc/dnsmasq.d/home.conf）
- **プロキシ**: nginxサーバー設定を拡張（プロキシ先を3001ポートに変更）
- **VPN**: 既存Tailscale環境をそのまま活用

### 3.2 ディレクトリ構造
```
/release/
├── 002--claude-test/           # ステージング環境ルート
│   ├── frontend/               # Next.js アプリケーション
│   │   ├── .next/             # Next.js ビルド成果物
│   │   ├── src/               # ソースコード
│   │   ├── public/            # 静的アセット
│   │   ├── package.json       # 依存関係
│   │   └── next.config.js     # Next.js設定
│   ├── backend/               # FastAPI アプリケーション
│   │   ├── app/               # アプリケーションコード
│   │   ├── requirements.txt   # Python依存関係
│   │   └── main.py           # FastAPIエントリーポイント
│   ├── config/                # 環境設定
│   │   ├── staging.env        # ステージング環境変数
│   │   ├── nginx.conf         # nginxサーバー設定
│   │   └── pm2.config.js      # プロセス管理設定
│   └── scripts/               # 運用スクリプト
│       ├── deploy.sh          # デプロイスクリプト
│       ├── start.sh           # サービス起動
│       └── stop.sh            # サービス停止
```

### 3.3 技術スタック仕様

#### フロントエンド
- **Next.js 14**: React フレームワーク（既存実装活用）
- **TypeScript**: 型安全性の確保
- **TailwindCSS**: 既存UIスタイル継続使用
- **認証状態管理**: useAuth hook（既存実装活用）

#### バックエンド  
- **FastAPI**: Python Webフレームワーク（高速・非同期）
- **JWT認証**: JSON Web Token による認証管理
- **HTTPOnly Cookie**: セキュアなセッション管理
- **CORS設定**: フロントエンドとの適切な連携
- **SQLite/PostgreSQL**: セッション・ユーザーデータ永続化
- **Pydantic**: リクエスト・レスポンス検証

#### API設計
- **REST API**: `/api/auth/*` 認証関連エンドポイント
- **WebSocket**: リアルタイム通知（将来拡張）
- **OpenAPI**: Swagger自動生成ドキュメント
- **バージョニング**: `/api/v1/` による後方互換性

### 3.4 セキュリティ要件

#### SEC-001: 認証・認可
- **JWT認証**: アクセストークン + リフレッシュトークンの管理
- **セッション管理**: HTTPOnly + Secure + SameSite設定
- **CSRF対策**: CSRFトークンによるリクエスト検証
- **セッション有効期限**: アクセストークン1時間、リフレッシュトークン7日間
- **自動ログアウト**: 非アクティブ状態24時間後

#### SEC-002: ネットワークセキュリティ
- **VPN限定アクセス**: Tailscaleネットワーク経由のみ
- **HTTPS対応**: Let's Encryptによる証明書取得（将来実装）
- **ファイアウォール**: 必要最小限のポート開放

## 7. リスク・課題

### 7.1 技術的リスク
- **ポート競合**: 3001、8000ポートの他プロセスとの競合可能性
- **リソース不足**: 既存サーバーでの複数サービス同時実行
- **プロキシ設定**: nginx設定変更による既存機能への影響

### 7.2 運用リスク
- **設定管理**: 複数環境（開発・ステージング）の設定混在
- **デプロイエラー**: 手動操作による設定ミス・サービス停止
- **セキュリティ**: 開発用認証の本番環境への誤用

### 7.3 対応策
- **事前検証**: ポート確認・リソース監視による事前チェック
- **設定分離**: 環境別設定ファイルの明確な分離管理
- **ロールバック**: 設定変更前のバックアップ・復旧手順確立

### 10.2 発見された技術的問題と解決策

#### 問題1: Next.js JavaScriptファイル400エラー
- **現象**: ログインページのJSファイル読み込み失敗（`page-xxx.js` 400 Bad Request）
- **原因**: ビルド後のファイル名変更とキャッシュの不整合
- **解決策**: 完全リビルド（`rm -rf .next node_modules` + `npm install` + `npm run build`）

#### 問題2: バックエンドAPI 500エラー
- **現象**: `/api/v1/auth/mock-login` エンドポイントで Internal Server Error
- **原因**: datetime import問題またはリクエストボディ処理エラー
- **解決策**: 一時的修正版バックエンド作成（`/tmp/temp_backend.py`）

#### 問題3: nginx プロキシ経由でのCORS問題
- **現象**: フロントエンドからAPIへの直接アクセス（port 8000）
- **解決策**: 相対パス使用（`/api/v1/auth/*`）でnginxプロキシ経由に変更
